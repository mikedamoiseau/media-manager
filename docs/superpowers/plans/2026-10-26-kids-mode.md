# Kids Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A profile can be a kids profile: on a phone in kids mode the child sees only titles fit for them, plays them on the TV, controls only pause/stop/volume/audio/subtitles, leaves only with the parents' code, and stops at bedtime; the same list is kept as a "Kids" tag in Kodi's library for the TV's kids view.

**Architecture:** Age ratings (Germany, France, US) are fetched from TMDB with each title's details and stored on `titles`. A new `server/kids.ts` holds the rule (which items a kid may see), overrides, the parents' code, bedtime and the list of routes a kids profile may call; the API applies it as a guard on every request that carries a kids profile. The web app reads the kid's allowed item ids once and filters its cached library with them, hides the grown-up screens, and asks the code to leave. A small `server/kidsTag.ts` keeps Kodi's "Kids" tag in step.

**Tech Stack:** Node 25 (TypeScript strip-only), Hono, node:sqlite, React 19 + Vite + wouter, node:test.

**Spec:** docs/superpowers/specs/2026-10-26-kids-mode-design.md

## Global Constraints

- Age limit steps (Germany's FSK): 0, 6, 12, 16. The owner's kid: 12.
- Rating used: Germany's (FSK) when there is one; else the stricter of France's and the US's. No rating at all: within age only in the KIDS folder (category `kids`).
- Made for kids: category `kids`, or TMDB genre `Family` or `Animation`.
- Allowed = override "OK for kids", or (made for kids and within age and no override "Not for kids"). Overrides are for the household (all kids); the age limit and bedtime are per kids profile.
- The main profile can't be a kids profile. One parents' code for the household, 4 digits; changed from any device not in kids mode, without the old code.
- Entering kids mode: no code. Leaving (switching to any other profile): the code.
- Bedtime: nothing new starts from kids mode from the bedtime until 6:00; what plays finishes; Kodi going on to the next episode of a kids play is stopped. Parents' plays are never stopped.
- Kids mode hides Settings, To review, the full Remote, TV power, the TV switcher, Play in VLC, trailers, matching, poster picker, hiding titles, people/sets/"elsewhere"/cinema/"Films to get", and the parents' override control. Kids may like/dislike.
- Kids now playing: pause/resume, stop, volume, audio language, subtitles; only on a title allowed for the kid, whoever started it; anything else shows only "something else is playing" (no title, no poster, no buttons).
- Kodi: the app writes only its own tag `Kids` (adds/removes it, keeps every other tag) and, at bedtime, `Player.Stop`. Nothing else changes in Kodi. Never run Clean library.
- The repository is public: no personal data (names, the kid's details, codes, keys, the sheet id) in code, tests or commits. `data/` stays git-ignored.
- Tests use `node:test`; every feature gets a Codex review before its commit is final; push only when the owner asks.

## Review Focus

1. A kids profile calling any route not meant for kids (`GET /api/elsewhere`, `POST /api/kodi/power`, `PUT /api/settings`, `POST /api/kodi/input`, `PUT /api/profiles/1`) gets 403 — pinned in Task 4 (`kidsRoute` table test).
2. A file in KIDS with no TMDB match (no title, no ratings) is allowed — pinned in Task 3.
3. Two kids profiles with different limits: Kodi's tag holds only titles allowed for both — pinned in Task 8.
4. Bedtime around midnight: bedtime 20:00 and bedtime 00:30, at 23:59, 00:29, 05:59, 06:00 — pinned in Task 5.
5. Play pressed just before bedtime, Kodi's play event arriving just after: not stopped (only plays Kodi chained by itself are) — pinned in Task 5.
