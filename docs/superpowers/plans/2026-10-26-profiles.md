# Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each person picks who they are on their device and gets their own Continue watching, progress, likes and suggestions; the library stays shared.

**Architecture:** A `profiles` table, with per-profile copies of everything personal: `film_states` and `episode_states` (Kodi-style progress per profile), plus `profile_id` on `watching`, `ratings` and `activity`. Kodi stays one shared library: after each sync, the rows whose Kodi state changed are copied to the profile that started that play (`tv_plays`, filled from the Play endpoint and from Kodi's player events), or to the main profile. The web app keeps the chosen profile in `localStorage` and sends it as `x-profile` (VLC links carry `p`).

**Tech Stack:** Node 25 (TS strip-only), Hono, node:sqlite, React 19 + Vite + wouter, node:test.

**Spec:** `docs/superpowers/specs/2026-10-26-profiles-design.md`

## Global Constraints

- Public repo: no personal names or data in code. Main profile default name `Me`.
- Main profile id is `1` (`MAIN_PROFILE`); it can't be removed.
- No passwords on profiles.
- Shared, unchanged: library contents, matches, posters, hidden, settings, TVs, `picks` ("Films to get" and "not interested"), reports, cinemas row, home-row toggles (`mm.prefs`, per device).
- Kodi's own playcount/resume/last-played (`items`, `episodes` columns) keep being written by the sync, unchanged: they are Kodi's shared view.
- Checks: `npm run -s typecheck && npx tsc --noEmit -p web/tsconfig.json`, `npm test`, `npm run -s build`.
- Opening a title page POSTs `/api/items/:id/activity`: stub it in browser tests.
- Work on branch `feat/profiles`; commit per task; Codex review + `/code-review` before merging to `main`. No attribution lines in commits.

## Review Focus

1. A device whose profile was removed on another device: it must show "Who's watching?" again, not keep sending a dead id (Task 6: `chosenProfile` returns null for a removed id).
2. Play on TV while the app's event connection to that TV is down: the progress still goes to the device's profile (Task 4: attribution from the Play endpoint's `tv_plays` row alone).
3. The server restarts during a film: ownership must survive (Task 4: `tv_plays` is in the database; the attribution test uses no in-memory state).
4. Two profiles on the same film: one's Play on TV must not start at the other's point (Task 5: `startPoint` per profile).
5. A series watched by someone else after main's last play: main's next episode must not move (Task 3: `nextEpisode` per profile).

### Task 4: Whose play it is on a TV

**Files:**
- Create: `server/owners.ts`
- Modify: `server/kodiEvents.ts`, `server/service.ts`, `server/api.ts`
- Test: `tests/owners.test.ts`, `tests/kodi-events.test.ts`

**Interfaces:**
- Consumes: Tasks 1 and 3 tables.
- Produces:
  - `class TvOwners { touch(tvId: string, profileId: number, now: number): void; start(tvId: string, now: number): number; stop(tvId: string, ended: boolean, now: number): void }`. `start` returns the profile that touched that TV within `TOUCH_WINDOW = 3 * 60_000`, else the owner of the previous play on that TV when it ended (`ended: true`) within `CHAIN_WINDOW = 2 * 60_000` before (Kodi playing the next episode), else `MAIN_PROFILE`.
  - `notePlay(db, kodiType: 'movie' | 'episode', kodiId: number, profileId: number, now: number): void` (upsert `tv_plays`).
  - `interface KodiStates { films: Map<number, State>; episodes: Map<number, State> }` with `State = { kodiType: 'movie' | 'episode'; kodiId: number; playcount: number | null; resume: number | null; lastPlayed: string | null }`; `kodiStates(db): KodiStates` (films: items with `kodi_type = 'movie'`; episodes with a `kodi_id`); `attributeKodiChanges(db, before: KodiStates): number` (rows whose Kodi state differs from `before`; owner = the `tv_plays` row for that Kodi item when its `at` is after the previous `last_played` minus 5 minutes (or there was none), else `MAIN_PROFILE`; the owner's state row gets the new `resume` and `last_played`, its `playcount` grows by the increase, or becomes 0 when Kodi's became 0; returns how many rows were given).
  - `KodiEvents` constructor gains `onPlayer?: (e: { kind: 'play' | 'stop'; item?: { type: string; id: number }; ended?: boolean }) => void` (4th parameter), fired on `Player.OnPlay` (`params.data.item`) and `Player.OnStop` (`params.data.item`, `params.data.end`).
- Wiring: `Service` holds one `TvOwners`; each TV's `KodiEvents` gets `onPlayer`: `play` with item type `movie`/`episode` → `notePlay(db, type, id, owners.start(tv, now), now)`; `stop` → `owners.stop(tv, !!ended, now)`. `syncKodiOnce`: `const before = kodiStates(db)` before `syncFromKodi`, `attributeKodiChanges(db, before)` after. `api.ts`: `/items/:id/play` calls `owners.touch(tv, p)` and, for a Kodi library film or episode, `notePlay(db, …, p, now)` itself; `/kodi/remote` and `/kodi/input` call `owners.touch(tv, p)`. The TV id is the one `kodi(c)` resolved.

In `tests/kodi-events.test.ts`: `player events are passed on` (feed `Player.OnPlay` with `{item:{type:'movie',id:12}}` and `Player.OnStop` with `{item:{…},end:true}` through the fake pipe; assert the two callbacks).
